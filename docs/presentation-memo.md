### ดอส — สไลด์ 2–4 (≈3 นาที)

**สไลด์ 2 Problem**
- คนวัยทำงานมีปัญหาการนอน โดยเฉพาะนอนไม่หลับและหยุดหายใจขณะหลับ
- การตัดสินใจที่ต้องการ: จะเฝ้าระวัง ปรับพฤติกรรม หรือส่งต่อแพทย์

**ประโยค decision statement**
> โมเดลนี้ช่วยแพทย์/บุคลากร wellness จำแนกความเสี่ยงการนอนและแนะนำขั้นถัดไป จากข้อมูลไลฟ์สไตล์ หัวใจ และแบบคัดกรองอาการสั้นๆ

**สไลด์ 3 Justification**
- อ้าง 1–2 หลักฐานที่เตรียมไว้ (สถิติหรืองานวิจัย)  
- ย้ำว่าเป็น screening aid สำหรับงานวิชา

**สไลด์ 4 Stakeholders**
| ใคร | ต้องการอะไร |
| --- | --- |
| แพทย์ | ข้อมูลช่วยตัดสินใจส่งตรวจต่อหรือไม่ |
| บุคลากร wellness | คำแนะนำขั้นถัดไปที่ชัด |
| ผู้ใช้ | รู้ว่าควรทำอะไร โดยไม่ถูกหลอกว่าเป็นวินิจฉัย |

ส่งไม้ต่อด๋อย

### ด๋อย — สไลด์ 5–7 (≈3 นาที)

**สไลด์ 5 Objectives**
1. หาความสัมพันธ์ของไลฟ์สไตล์/หัวใจ กับป้ายความผิดปกติการนอน  
2. ออกแบบ hybrid: กฎคัดกรอง + ML เชิงลึก  
3. แปลงผลเป็น action  
4. ประเมินด้วย CV และเกณฑ์สำเร็จที่วัดได้

**สไลด์ 6 Dataset**
- Sleep Health and Lifestyle Dataset · Laksika Tharmalingam · Kaggle  
- 374 แถว · 13 คอลัมน์  
- เป้า: None 219 / Insomnia 77 / Sleep Apnea 78  
- สำคัญ: ผู้เผยแพร่ระบุว่าเป็นข้อมูล synthetic เพื่อประกอบการสาธิต

**สไลด์ 7 Quality**
- เก็บป้าย `None` ไม่ให้หายตอนอ่านไฟล์  
- แมป Normal Weight → Normal  
- แยกความดันเป็นตัวบน/ตัวล่าง  
- มีแถวซ้ำ 265 แถว → คะแนน CV อาจดูสูงเกินจริง  
- class imbalance ใช้ `class_weight=balanced`

### บอส — สไลด์ 10–12 (≈3 นาที)

**สไลด์ 10 Decision model**
- Hybrid จริงๆ คือ: **Rule triage → Random Forest → Decision layer**
- RF ใช้ฟีเจอร์ไลฟ์สไตล์/หัวใจเท่านั้น  
- คำตอบ pre-screen ไม่ถูกฝึกในป่าสุ่ม เพราะ CSV ไม่มีป้ายของ 13 ข้อ — ไปปรับชั้นตัดสินใจแทน

**สไลด์ 11 Workflow**
พูดคร่าว 10 ขั้น แล้วเน้น:
- ขั้นคัดกรองล็อกไม่ให้ข้ามฟอร์มลึก  
- ขั้น 10 มี feedback ในเดโมแล้ว (local file)

**สไลด์ 12 Evaluation**
| โมเดล | Accuracy | Macro F1 |
| --- | ---: | ---: |
| LogReg | 0.904 | 0.884 |
| Tree | 0.866 | 0.845 |
| **RF** | **0.909** | **0.885** |

เกณฑ์สำเร็จ:
- เทคนิค: F1 ≥ 0.80 และ accuracy ≥ 0.85 → ผ่าน  
- Usefulness: feedback useful ≥ 80% → วัดตอนซ้อม/เดโม

Caveat: แถวซ้ำทำให้คะแนนอาจดูดีเกิน

ส่งไม้กลับเฟรม

### เฟรม — สไลด์ 13–14 + เดโมสด (≈2–3 นาที)

**สไลด์ 13 Decision rules (พูดก่อนเดโม 30 วินาที)**
- Insomnia ติดเมื่อ ≥2 ข้อ  
- Apnea ติดเมื่อ ≥2 ข้อ หรือ red-flag (หยุดหายใจ / สำลัก / หลับตอนขับรถ)  
- ความมั่นใจโมเดลแบ่ง `<0.40` / `0.40–0.69` / `≥0.70`  
- ถ้า pre-screen กับโมเดลขัดกัน → บังคับพบแพทย์

**เดโมสด (อย่าเกิน 2 นาที)**

1. กด Deep assess ก่อน → โชว์ว่าถูกล็อก  
2. Screening: ใช่แค่กรน → ได้ None  
3. ล้างแล้วใช่ข้อหยุดหายใจ → ติด Apnea → ไปลึกได้  
4. กรอกโปรไฟล์ ก (ชาย อายุ 55 พยาบาล น้ำหนัก 102 ส่วนสูง 170 ความดัน 140/90)  
5. หน้า Result: ชี้ pre-screen vs model, hybrid, คำแนะนำ  
6. กด Feedback Useful หนึ่งครั้ง

**ประโยคปิดเดโม**
> เดโมนี้แสดงครบเส้นทาง Problem → Data → Model → Decision → Action และมี feedback เป็นต้นแบบขั้นที่ 10

### ดอส — สไลด์ 15 ปิด (≈1 นาที)

**Benefits**
- คัดกรองเร็วขึ้น  
- action ชัด  
- โปร่งใสเรื่องความน่าจะเป็นและความขัดแย้งของสองขั้น

**Limits / ethics**
- ข้อมูล synthetic + แถวซ้ำ  
- ไม่ใช่เครื่องมือคลินิกที่ validate  
- ต้องมีคนดูแลตัดสินใจสุดท้าย  
- feedback ยังเป็น log ท้องถิ่น ไม่ใช่ฐานข้อมูลโรงพยาบาล

**Closing**
> สรุปครับ กลุ่มเราสร้างต้นแบบ decision support ที่คัดแยกผู้เสี่ยงก่อน แล้วประเมินเชิงลึกด้วยโมเดล พร้อมกฎตัดสินใจและข้อจำกัดที่เปิดเผย  
> พร้อมรับคำถามครับ

## Cheat sheet ตอบคำถามอาจารย์

| คำถามที่โดนบ่อย | คำตอบสั้น |
| --- | --- |
| นี่คือ AI วินิจฉัยไหม? | ไม่ใช่ครับ เป็น screening / decision support สำหรับงานวิชา แพทย์เป็นผู้วินิจฉัย |
| ทำไมขั้นแรกไม่ใช้ ML? | ชุดข้อมูลไม่มีป้ายของคำถาม 13 ข้อ ถ้าฝืนใส่จะไม่มีคู่ฝึกที่สุจริต จึงใช้กฎก่อน แล้วค่อย RF กับฟีเจอร์ที่มี |

| ถ้าสองขั้นตอบคนละอย่าง? | ระบบบังคับ clinical review ไม่ยอมให้เลือกผลที่สบายกว่า |
| ทำไมไม่ครอบคลุม RLS/Narcolepsy? | โมเดลและข้อมูลรองรับแค่ None / Insomnia / Sleep Apnea |
