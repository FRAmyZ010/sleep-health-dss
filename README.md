## Deploy บน Render (ฟรี)

ให้ลิงก์สาธารณะให้อาจารย์เปิดจากภายนอกได้ โดยใช้ Blueprint ใน `render.yaml`

1. Push โค้ดขึ้น GitHub (รวม `server.py`, `render.yaml`, `requirements.txt`, โฟลเดอร์ `web/`)
2. เปิด [Render](https://render.com) → **New** → **Blueprint** → เลือก repo นี้
3. ยืนยัน service `sleep-health-dss` (plan Free) แล้ว Deploy
4. รอ build เสร็จ แล้วใช้ URL ที่ Render ให้ เช่น `https://sleep-health-dss.onrender.com`

หรือสร้าง **Web Service** มือ: Build `pip install -r requirements.txt` / Start `uvicorn server:app --host 0.0.0.0 --port $PORT` / Python 3.11

ข้อจำกัด Free ที่ควรบอกอาจารย์:

- ครั้งแรกหลังไม่ได้ใช้สักพักจะ **cold start** ประมาณ 30–60 วินาที (บางครั้งนานกว่า)
- ดิสก์ชั่วคราว — log ใน SQLite (`data/assessments.db`) **อาจหาย** หลัง redeploy/รีสตาร์ท
- หน้าเว็บเปิดสาธารณะสำหรับใครที่มีลิงก์ (ไม่ใส่รหัสผ่าน)

ตรวจหลังขึ้น: เปิด URL → `#screen` ตอบครบ → ไป `#assess` / `#result` ได้

## การไหลสองขั้น

1. **คัดกรองอาการ** (`#screen`) — ตอบ 13 ข้อด้วย**กฎ** (ไม่ใช่ ML) จัดเข้า `None` / `Insomnia` / `Sleep Apnea` ข้อกรนและมีผู้เห็นหยุดหายใจมีตัวเลือก **ไม่ทราบ / อยู่คนเดียว** (ไม่นับเป็น hit) พร้อมคะแนน STOP-Bang / ISI-inspired แบบคู่ขนาน (ดู `docs/screening-standards-mapping.md`)
2. **ประเมินเชิงลึก** (`#assess` → `#result`) — เปิดได้หลังทำ triage ครบ ค่าไลฟ์สไตล์/ชีพจรแนะนำจาก **สมาร์ทวอทช์ทั่วไป** (มีปุ่มเดโม) แล้ว Random Forest ให้คลาส + ความน่าจะเป็น **ไม่ใช้ความดัน**
3. **ตัดสินใจสุดท้าย** — ใช้ช่วงความมั่นใจ (`<0.40` / `0.40–0.69` / `≥0.70`) หลักฐานจาก pre-screen และบังคับพบแพทย์เมื่อสองขั้นขัดกัน
4. **บันทึกและตรวจสอบ (ขั้นที่ 10)** — หลังประเมินสำเร็จ ระบบเก็บผลแบบ **anonymous** ใน SQLite (`data/assessments.db`) ดูได้ที่ `#logs` / ส่งออก CSV และดู proxy ground truth ที่ `#trust`  
   ก่อนบันทึกแต่ละครั้ง ระบบดึงเคสคล้ายจาก log (คลาสหน้าจอ+โมเดล, อายุ ±10, BMI หมวดเดียวกัน; ขั้นต่ำ 3 เคส) มาแสดงบน `#result` และอาจ**ยกระดับ**ความระมัดระวังหนึ่งขั้นถ้า conflict ≥40% หรือ High ≥50% (ไม่ลด risk)  
   **Future work:** ยังไม่มี outcome feedback จากผู้ใช้หรือแพทย์ และยังไม่ปิด loop ไป retrain อัตโนมัติ

| กลุ่มจากแบบคัดกรอง | เงื่อนไขติดกลุ่ม | ขั้นถัดไป |
| --- | --- | --- |
| None | ไม่ครบเกณฑ์ด้านล่าง | สรุปผล; จบได้ หรือเลือกไปประเมินเชิงลึกต่อ |
| Insomnia | ตรงอย่างน้อย 2 จากข้อ 1, 6, 9 | เข้าประเมินเชิงลึก + โมเดล |
| Sleep Apnea | ตรงอย่างน้อย 2 จากข้อในกลุ่ม หรือใช่ red-flag ข้อ 3, 4 หรือ 12 | เข้าประเมินเชิงลึก + โมเดล |

## หน้าในเดโม

หน้าอยู่ที่แฮชเหล่านี้

- `#screen` คัดกรองอาการ 13 ข้อ (มี Unknown ในข้อที่พึ่งพาคู่) แล้วแสดงผลกฎ triage + คะแนนมาตรฐานคู่ขนาน
- `#assess` กรอกข้อมูลสี่ขั้น: ตัวคุณ / การนอนจาก watch / ชีพจรจาก watch / ตรวจทาน (อายุรับได้ 1–120)
- `#result` แสดงคลาสที่ทำนาย ความน่าจะเป็น ปัจจัย คำแนะนำ และคะแนนมาตรฐานที่เติมจากฟอร์มลึก
- `#logs` ดู anonymous assessment log + ดาวน์โหลด CSV สำหรับ Google Sheets
- `#trust` สรุป proxy ground truth (Kaggle CV) + โปรไฟล์อ้างอิง + mapping มาตรฐาน
- `#eda` สำรวจตารางฝึก ตัวกรองเปลี่ยนกราฟ แต่ไม่เปลี่ยนคะแนน cross-validation

ภาษาเริ่มต้นเป็นอังกฤษ สลับเป็นไทยได้ที่ปุ่มธง และค่าที่เลือกถูกเก็บในเบราว์เซอร์ ปุ่มเริ่มจากหน้าแรกพาไป `#screen` ก่อน ค่าเริ่มของฟอร์มเชิงลึกคือหญิงอายุ 40 ปี อาชีพ Nurse น้ำหนัก 70 กก. ส่วนสูง 170 ซม. ได้ BMI 24.2 หมวดปกติ

น้ำหนักและส่วนสูงไม่มีในไฟล์ข้อมูล เซิร์ฟเวอร์คำนวณ BMI แล้วส่งเฉพาะหมวดเข้าโมเดล เกณฑ์ WHO คือต่ำกว่า 18.5 น้ำหนักน้อย, 18.5 ถึงต่ำกว่า 25 ปกติ, 25 ถึงต่ำกว่า 30 น้ำหนักเกิน, และ 30 ขึ้นไปอ้วน ความดันใน CSV ถูกตัดออกจากฟีเจอร์โมเดลเพื่อให้สอดคล้องกับค่าที่สมาร์ทวอทช์ทั่วไปมี

## ข้อมูลและโมเดล

ไฟล์ที่ใช้ฝึกคือ `Sleep_health_and_lifestyle_dataset.csv` มี 374 แถว ชุดข้อมูลสาธารณะชื่อ Sleep Health and Lifestyle Dataset ผู้เผยแพร่คือ Laksika Tharmalingam ปี 2023

https://www.kaggle.com/datasets/uom190346a/sleep-health-and-lifestyle-dataset

ป้ายในไฟล์มี `None` 219 แถว, `Sleep Apnea` 78 แถว และ `Insomnia` 77 แถว ระบบอ่านป้าย `None` เป็นคลาสจริง ไม่ได้ทิ้งเป็นค่าว่าง หมวด `Normal Weight` 21 แถวถูกแปลงเป็น `Normal` ก่อนฝึก ความดันในไฟล์ยังอยู่ใน CSV แต่**ไม่เข้าโมเดล** (`MODEL_VERSION` 2)

โมเดลคือ `RandomForestClassifier` ด้วย `n_estimators=300`, `min_samples_leaf=2`, `class_weight="balanced"`, `random_state=42` และ `n_jobs=1` ตัวแปรหมวดใช้ one-hot ตัวเลขถูกลดสเกล การประเมินเป็น stratified 5-fold จากตารางเดียวกัน ได้ accuracy 0.904 ± 0.037 และ F1 macro 0.881 ± 0.044 (หลังตัดความดันออกจากฟีเจอร์) แถวที่คุณลักษณะซ้ำมี 265 แถว คะแนนนี้จึงอาจสูงเกินผลกับคนใหม่

ความเสี่ยงสุดท้ายมาจากชั้นตัดสินใจ ไม่ใช่คลาสโมเดลอย่างเดียว: ใช้ช่วงความมั่นใจ ความขัดแย้งกับ pre-screen และหลักฐานจากหน้าจอ รายละเอียดอยู่ใน `docs/report-supporting-content.md`

อาชีพ `Other` เลือกได้ในฟอร์ม แต่ไม่มีในตารางฝึก ตัวเข้ารหัสถือว่าเป็นค่าที่ไม่เคยเห็น พจนานุกรมคอลัมน์อยู่ที่ `docs/data-dictionary.md` เช็กลิสต์ซ้อมเดโมอยู่ที่ `docs/demo-rehearsal-checklist.md`

ตรวจก่อนเดโมด้วยคำสั่งเหล่านี้

```powershell
python scripts\check_triage.py
python scripts\check_ground_truth.py
python scripts\check_doctor_gate.py
python model.py
```

`check_triage.py` ตรวจเกณฑ์ pre-screen, red-flag, conflict และช่วงความมั่นใจ  
`check_ground_truth.py` สรุป proxy GT จาก Kaggle CV และโปรไฟล์อ้างอิง  
`check_doctor_gate.py` เทียบ GT หลักกับเกณฑ์ “ควรพบหมอ” / แบบสอบถาม (ส่งออก CSV ใน `artifacts/`)  
`model.py` ฝึกใหม่ทุกครั้ง แล้วพิมพ์จำนวนแถว คะแนน cross-validation และผลทำนายของแถวตัวอย่าง
